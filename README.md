# サロン経営タイプ診断アプリ

エステティック通信公式LINEの友だち獲得キャンペーン用の診断コンテンツ（[Chat21統合ランキング](../01_DeepResearchレポート/プレゼントキャンペーン統合ランキング_20260818.html) Sランク1位施策）。

MBTI（16Personalities）のような「二択カード形式」で8問に答え、さらに**自社HP・ホットペッパービューティー・Instagramの実データ**を分析に加えることで、サロン経営スタイルを**16タイプ**の中から診断する。結果はレーダーチャート・軸ごとの割合バー・実データダッシュボードで可視化する。**エステティック通信公式LINEの友だちであること**が利用条件（LIFF連携によるゲート）。

**公開URL**: https://msk1004.github.io/estsushindan0818/

## 全体フロー

```
① LINE友だちゲート（LIFF）
   └ 友だちでなければ「友だち追加してはじめる」を表示、友だちなら②へ
② イントロ
③ 8問クイズ（MBTI風二択カード）
④ URL入力（任意）— 自社HP／ホットペッパー／Instagram
⑤ 分析中（バックエンドでURLを取得・簡易解析）
⑥ 結果画面
   ├ 16タイプ診断（ゲージ付きバッジ・レーダーチャート・軸別割合バー）
   ├ WEB診断データ（口コミ件数・評価点・価格帯・フォロワー数 等）
   ├ 強み／伸ばすとさらに強くなる視点
   └ 「サロン経営 実践ノウハウBOOK」への導線（whitepaper.html）
```

## 診断の仕組み（16Personalities方式）

4つの特性軸 × 各2極 = 2⁴ = **16タイプ**。「良い/悪い」ではなく「経営スタイルの違い」として設計。

| 軸 | 極A | 極B |
|---|---|---|
| 集客スタイル | 🧲 新規開拓型（G） | 🤝 常連育成型（E） |
| 価値提供スタイル | 💎 単価特化型（P） | ⚡ 回転重視型（V） |
| 運営体制スタイル | 🧵 一人型（S） | 🌳 チーム型（T） |
| 意思決定スタイル | 🔮 感覚型（I） | 📐 データ型（D） |

各軸2問・計8問のクイズ回答に加え、**実データを取得できた場合はその内容で軸%を穏やかに補正**してからタイプを確定する（`script.js` の `applyWebDataNudge`）。例：Instagramフォロワー数が多い→新規開拓寄りに補正、ホットペッパーの価格帯が高い→単価特化寄りに補正、など。取得できなかった項目は補正なし（クイズ回答のみで判定）。

## 実データ分析について（重要な制約）

ブラウザは他サイトを直接fetchできない（CORS）ため、Google Apps Scriptをサーバー代理として使い、`UrlFetchApp`で対象URLを取得・簡易解析している（`apps-script/Code.gs`）。

| 対象 | 取得の安定性 | 抽出する項目 |
|---|---|---|
| 自社HP | 高い（自分のサイトなので安定） | ブログ/お知らせの有無・予約導線の有無・SNS連携の有無・情報量の目安 |
| ホットペッパービューティー | 中（ページ構造の変更に弱い） | 口コミ件数・評価点・価格帯・掲載メニュー数 |
| Instagram | **低い**（公開ページの大半がJS描画のため、素の取得ではほぼ拾えない） | 取得できた場合のみフォロワー数・投稿数 |

いずれも取得失敗時は `null` を返し、フロント側は「WEB診断データ」パネルに該当タイルを「取得不可」として表示するだけで、診断自体は止まらない設計にしている。**保証された正確な値ではなく、あくまで簡易ベストエフォートの参考値**であることを画面上にも明記している。

## LINE友だちゲート（LIFF）について

`CONFIG.LIFF_ID` が未設定の間は、ゲート自体をスキップして誰でも診断できる（開発・確認用のフェイルオープン挙動）。本番運用時は以下を設定するとゲートが有効になる。

1. [LINE Developers コンソール](https://developers.line.biz/) で、公式アカウントに紐づくチャネルにLIFFアプリを追加
   - エンドポイントURL: `https://msk1004.github.io/estsushindan0818/`
   - Scope: `profile`
2. 発行された **LIFF ID** を `script.js` の `CONFIG.LIFF_ID` に設定
3. LINEアプリ内（トークのリッチメニューやメッセージのリンク経由）で開かれた場合、`liff.getFriendship()` で友だち判定を行う
4. LIFF外のブラウザで開かれた場合や判定APIが使えない場合は、フェイルオープン（診断は使える状態）にして機会損失を防いでいる

## 公開前に設定する項目（script.js 冒頭 `CONFIG`）

| 項目 | 内容 |
|---|---|
| `LINE_ADD_FRIEND_URL` | LINE公式アカウントの友だち追加リンク |
| `LIFF_ID` | LINE Developersで発行するLIFF ID。未設定なら友だちゲートをスキップ |
| `API_ENDPOINT` | 診断ログ記録・URL分析を行うApps Script Web AppのURL。未設定ならログ記録・URL分析ともにスキップ（クイズのみで診断は動作する） |

## バックエンド（Apps Script）のセットアップ

1. 記録用のGoogleスプレッドシートを新規作成
2. 「拡張機能」→「Apps Script」を開き、`apps-script/Code.gs` の内容を貼り付けて保存
3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」／実行ユーザー「自分」／アクセス「全員」で発行
4. 発行されたURLを `script.js` の `CONFIG.API_ENDPOINT` に貼り付けてコミット

診断ログは「診断ログ」シートに、URL分析結果は「URL分析ログ」シートに、それぞれ自動で追記される。個人情報（氏名・連絡先等）は一切扱わない。

## 結果の共有・リサーチ活用

- 診断完了時にURLが `?type=GPSI` のように書き換わり、共有・再訪問に使える
- 「結果をコピーしてシェア」ボタンでURLをクリップボードにコピー可能
- ログを有効化すると、8問の回答・タイプコード・軸スコア・実データ活用有無がスプレッドシートに蓄積され、サロン経営者の傾向分析やメーカー営業への示唆抽出に利用できる
