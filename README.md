# サロン経営タイプ診断アプリ

エステティック通信公式LINEの友だち獲得キャンペーン用の診断コンテンツ（[Chat21統合ランキング](../01_DeepResearchレポート/プレゼントキャンペーン統合ランキング_20260818.html) Sランク1位施策）。

[16Personalities](https://www.16personalities.com/ja/性格診断テスト)のデザイン言語（ロールグループごとの2色パレット・物語調のタイプページ・相性タイプ表示）を踏襲しつつ、**エステサロン経営者向けに6タイプへ再設計**。MBTI風の二択カードで8問に答え、さらに**自社HP・ホットペッパービューティー・Instagramの実データ**を分析に加えて、経営タイプを診断する。

**公開URL**: https://msk1004.github.io/estsushindan0818/

## 全体フロー

```
① LINE友だちゲート（LIFF）
② イントロ
③ 8問クイズ（MBTI風二択カード）
④ URL入力（任意）— 自社HP／ホットペッパー／Instagram
⑤ 分析中（バックエンドでURLを取得・簡易解析）
⑥ 結果画面（16Personalities風のタイプページ構成）
   ├ ロールグループチップ＋タイプバッジ（グループカラーで自動着色）
   ├ タイプ概要（物語調・複数段落＋名言風の一言）
   ├ 強み／気をつけたいポイント
   ├ WEB診断データ（実データ）
   ├ マーケティング診断パネル（実データ入力時のみ表示）
   │  ├ デジタル接客力スコア（0〜100）
   │  ├ よく見えるキーワード
   │  ├ SWOT分析（強み・弱み・機会・脅威）
   │  ├ 3C分析（自社・顧客・市場動向）
   │  └ STP（セグメント・ターゲット・立ち位置）
   ├ 4軸プロファイル（レーダーチャート＋割合バー）
   ├ 相性の良いタイプ（クリックでそのタイプの結果に直接ジャンプ）
   └ Salon Leaders（集客システム）への導線
```

## 6タイプ診断の仕組み

16Personalities同様、**3つのロールグループ × 2タイプ = 6タイプ**の構成。4軸（集客・価値提供・運営体制・意思決定）のクイズ回答（＋実データ補正）を、6つの代表的な経営タイプ「セントロイド」に最も近いものへ最近傍法で分類する（`script.js` の `classifyType`）。

| グループ | カラー | タイプ | キャッチコピー |
|---|---|---|---|
| 🧡 魅せる系（新規開拓と拡散に強い） | コーラル | ✨ トレンドクリエイター型 | 話題を作り、勢いでサロンを広げるムードメーカー |
| | | 🎬 ブランドプロデューサー型 | データと世界観で、サロンをブランドに育てる |
| 💜 深める系（関係性と世界観づくりに強い） | プラム | 🎨 匠のアーティスト型 | 一人で丁寧に、特別な世界観を届ける |
| | | 🍵 おもてなしの達人型 | チームの温かさで、常連との絆を育てる |
| 💙 支える系（仕組みと安定運営に強い） | ティール | 📋 堅実オペレーター型 | 数字の裏付けで、一人でも堅実に運営する |
| | | 📈 システムリーダー型 | データとチームで、仕組みから拡大する |

各タイプページには、16Personalities同様に「タイプ概要（物語調）」「強み」「気をつけたいポイント」「名言風の一言」「相性の良いタイプ」を用意し、単なる診断結果ではなく読み物として楽しめる分量・質にしている。

## 実データ分析について（重要な制約）

ブラウザは他サイトを直接fetchできない（CORS）ため、Google Apps Scriptをサーバー代理として使い、`UrlFetchApp`で対象URLを取得・簡易解析している（`apps-script/Code.gs`）。

| 対象 | 取得の安定性 | 抽出する項目 |
|---|---|---|
| 自社HP | 高い | ブログ/お知らせの有無・予約導線の有無・SNS連携の有無・情報量の目安 |
| ホットペッパービューティー | 中（ページ構造の変更に弱い） | 口コミ件数・評価点・価格帯・掲載メニュー数 |
| Instagram | **低い**（公開ページの大半がJS描画） | 取得できた場合のみフォロワー数・投稿数 |

取得失敗時は診断を止めず「取得不可」と表示するだけの設計。**保証された正確な値ではない**ことを画面上にも明記している。

## マーケティング診断パネル（SWOT / 3C / STP）について

URL入力で実データが1件でも取得できた場合、結果画面に「マーケティング診断パネル」を追加表示する（`script.js` の `buildMarketingAnalysis`）。取得できた口コミ件数・評価点・価格帯・メニュー構成・発信有無・キーワード出現頻度だけを根拠に、ルールベース（if/thenの閾値判定）で以下を自動生成する。LLM呼び出しは行わないため、URL分析から結果表示まで数秒で完結する。

- **デジタル接客力スコア（0〜100）**: 予約導線・発信チャネル数・評価点・口コミ件数・メニュー幅・フォロワー数を重み付け合成した指標
- **よく見えるキーワード**: サイト・口コミページのテキストから固定辞書（丁寧・雰囲気・駅近・技術力 等14語）の出現頻度を集計
- **SWOT分析**: 上記の実測値に対する閾値判定（例: 評価4.5以上→強み、口コミ20件未満→弱み）。該当データが無い項目は空欄のまま表示し、埋め合わせの創作はしない
- **3C分析**: 自社＝取得データの要約、顧客＝キーワード傾向と価格帯からの推定ターゲット、市場動向＝業界全体の一般的な傾向（このサロン固有の競合分析ではない）
- **STP**: 価格帯（¥6,000/¥15,000を閾値）からセグメントを推定し、最も強いSWOT項目と組み合わせてポジショニング文を自動生成

### あえて「商圏マッチ率」は実装していない

商圏内の競合密度・人流データは、Google Places API等の有料GISデータ基盤が必要で、現在のスタック（静的サイト＋Apps Script）だけでは取得できない。実装しても値を捏造することになるため、**取得できた自社データだけで計算可能な「デジタル接客力スコア」に置き換えている**。真の商圏分析を行うには、別途GIS/POIデータAPIとの連携が必要（将来拡張の余地として記録）。

## 結果画面のCTA：Salon Leaders誘導について

診断結果の最後のCTAは、エス通の新規事業「[Salon Leaders](https://salon-leaders.co.jp/sl/)」（HP制作・MEO・SNS・予約・競合分析をまとめた月額集客システム）への導線にしている（`index.html` の `.cta-card` / `#slBtn`）。

診断結果で示される「弱み」「伸ばすとさらに強くなる視点」は、Salon Leadersが解決する領域（HP・MEO・SNS・競合分析）とそのまま重なるため、「診断で気づいた課題→Salon Leadersで仕組み化」という一貫した流れになるよう文言を設計している。リンク先URLは固定（`https://salon-leaders.co.jp/sl/`）で、外部サイトのため新規タブで開く。

以前バージョンにあった「サロン経営 実践ノウハウBOOK」（`whitepaper.html`）は提供を終了し、ファイルごと削除済み。

## タイプ別キャラクターアイコン（少女漫画風）の作り方

`script.js` の `setResultMascot()` は、`images/type-{コード小文字}.png`（例: `images/type-tc.png`）が存在すればそれを自動表示し、無ければ絵文字にフォールバックする**画像なし運用可能な設計**。以下のプロンプトでChatGPT（画像生成）を使い、6枚を用意すれば差し替え不要でそのまま反映される。

### スタイル共通ルール（6枚すべてに付ける）

> 少女漫画（shoujo manga）風のキャラクターポートレートイラスト。日本のアニメ塗り、繊細で柔らかい線画、大きくきらめく瞳とハイライト、優しいセルシェーディング。バストアップ構図、中央配置、背景はキャラクターごとの色味を活かしたソフトフォーカスのグラデーション＋星や花びらなどの淡いきらめき。文字・ロゴなし。1体のみ。1:1の正方形構図。高品質なデジタルイラスト。

### 一貫性を保つコツ

1. **同じChatGPTスレッド内で6枚連続生成する**（新しいチャットに分けない）。直前に生成した画像を参照させると画風が安定する
2. 1枚目を生成 → 気に入ったら「このキャラクターと同じ画風・同じ塗り方で、次は◯◯のキャラクターを描いて」と続けて指示する
3. 出力は正方形（1:1）、書き出しは1024×1024px以上のPNGを推奨
4. ファイル名は `images/type-tc.png` のように**タイプコードの小文字**にリネームしてこのフォルダの `images/` に置く（フォルダが無ければ新規作成）

### タイプ別プロンプト（共通ルールの後に続けて入力）

**TC｜トレンドクリエイター型（魅せる系・コーラル）**
> 元気で自信満々な短めのボブヘア、オレンジ〜コーラルのメッシュが入っている。スマートフォンを持ち、周りにきらきらエフェクト。ウインクしながらピースサイン。背景はコーラル×ピーチのグラデーションと星のきらめき。

**BP｜ブランドプロデューサー型（魅せる系・アンバー寄り）**
> セミロングの艶やかな髪を片方だけ耳にかけたスタイリッシュな女性。タブレットやムードボードを持ち、知的で余裕のある微笑み。アンバー〜ゴールドのアクセントカラーの衣装。背景はゴールドの光の粒子。

**AR｜匠のアーティスト型（深める系・プラム）**
> 黒髪ロングストレートを一部アップにまとめた、和のニュアンスがある女性。手に美容ブラシなど繊細な道具を持ち、落ち着いた優しい微笑み。プラム〜ローズのアクセントカラー。背景は柔らかい花びらが舞う演出。

**HS｜おもてなしの達人型（深める系・ローズピンク寄り）**
> ふんわりウェーブのミディアムヘア。ティーカップを持ち温かい笑顔、頬に手を添えた親しみやすいポーズ。ローズピンクのアクセントカラー。背景は暖かい光と小さなハートのきらめき。

**ST｜堅実オペレーター型（支える系・ティール）**
> 清潔感のあるショートヘアまたはハーフアップ。クリップボードを持ち、落ち着いた自信のある表情。きちんとした制服風の衣装。ティール〜ブルーのアクセントカラー。背景はチェックマークや幾何学的な淡い模様。

**SL｜システムリーダー型（支える系・ブルー〜インディゴ寄り）**
> クールなロングヘアの一部を三つ編みにしている。ノートパソコンやグラフチャートを持ち、自信に満ちた凛々しい表情。ブルー〜インディゴのアクセントカラー。背景は上昇するグラフラインの光のエフェクト。

> 補足: 今回セッション内で実際に生成を試みたが、画像生成クレジットが不足しており見本の生成はできなかった。上記プロンプトはそのまま貼り付けて使える状態にしてある。

## LINE友だちゲート（LIFF）について

`CONFIG.LIFF_ID` が未設定の間は、ゲート自体をスキップして誰でも診断できる（開発・確認用のフェイルオープン挙動）。本番運用時は以下を設定するとゲートが有効になる。

1. [LINE Developers コンソール](https://developers.line.biz/) で、公式アカウントに紐づくチャネルにLIFFアプリを追加
   - エンドポイントURL: `https://msk1004.github.io/estsushindan0818/`
   - Scope: `profile`
2. 発行された **LIFF ID** を `script.js` の `CONFIG.LIFF_ID` に設定
3. LINEアプリ内で開かれた場合、`liff.getFriendship()` で友だち判定
4. LIFF外や判定APIが使えない場合はフェイルオープン（診断は使える状態）

## 公開前に設定する項目（script.js 冒頭 `CONFIG`）

| 項目 | 内容 |
|---|---|
| `LINE_ADD_FRIEND_URL` | LINE公式アカウントの友だち追加リンク |
| `LIFF_ID` | LINE Developersで発行するLIFF ID。未設定なら友だちゲートをスキップ |
| `API_ENDPOINT` | 診断ログ記録・URL分析を行うApps Script Web AppのURL。未設定ならログ記録・URL分析ともにスキップ（クイズのみで診断は動作する） |

## バックエンド（Apps Script）のセットアップ

1. 記録用のGoogleスプレッドシートを新規作成
2. 「拡張機能」→「Apps Script」を開き、`apps-script/Code.gs` の内容を貼り付けて保存
3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」／実行ユーザー「自分」／アクセス「全員」で発行
4. 発行されたURLを `script.js` の `CONFIG.API_ENDPOINT` に貼り付けてコミット

診断ログは「診断ログ」シートに、URL分析結果は「URL分析ログ」シートに、それぞれ自動で追記される。個人情報は一切扱わない。
